# 仓库/市场重构场景流程梳理（建议稿）

> 目标：基于 `rebuild-task.md` 与 `docs/` 现有文档，梳理完整用户场景流程，补充当前问题与改进建议，用于后续重构与验收。 

---

## 1. 当前系统主要问题（归纳）

### 1.1 业务与用户体验问题

1. **数据断层导致闭环缺失**：用户添加仓库 → 扫描发现 Skills → 仅存本地缓存/仓库侧，**未进入市场数据库**，因此无法在市场安装，导致用户价值无法闭环。现状在 `rebuild-task.md` 的“当前问题”中已明确描述为“数据断层/功能闭环缺失”。【F:rebuild-task.md†L251-L276】
2. **入口与心智模型混乱**：侧边栏“市场”和“仓库管理”并列，但用户难以理解两者关系，**不知道扫描出的 Skills 去哪里**；文档中的用户心智模型与入口混淆问题已明确指出。 【F:rebuild-task.md†L200-L243】
3. **市场与仓库系统割裂**：仓库与市场数据表完全独立，**没有关联关系**，导致新增来源无法自然反映到市场。 【F:rebuild-task.md†L277-L295】

### 1.2 技术与文档一致性问题

1. **重构文档与代码/数据规则存在一致性风险**：`rebuild-task-review.md` 中指出时间戳单位、精选仓库 URL 等问题，影响数据一致性与初始化稳定性。 【F:docs/rebuild-task-review.md†L14-L105】
2. **删除仓库与已安装 Skill 的关系存在设计矛盾**：文档中 CASCADE 删除会导致已安装技能失去市场关联，后续更新不可见。 【F:docs/rebuild-task-review.md†L108-L170】

### 1.3 性能与扩展性问题

1. **Marketplace 数据量膨胀风险**：在后续规划中已提出需要从大体量 JSON 迁移到数据库并引入分页与缓存，说明当前做法存在性能隐患。 【F:docs/TOP-10-PRIORITIES.md†L242-L276】

## 2. 全面场景流程梳理（用户使用/操作/交互/管理）

> 说明：以下流程融合了 `rebuild-task.md` 设计目标与当前文档状态，分为“普通用户”和“高级用户/管理员”两类角色。

### 2.1 新用户初次使用（Onboarding / 发现市场）

**目标**：用户快速理解“市场=技能展示与安装入口”，“来源=技能数据源”。

**推荐流程**：
1. **启动应用** → 默认进入“市场”页。
2. **看到“官方精选来源”的技能列表**（已自动注入精选仓库）。【F:rebuild-task.md†L54-L85】
3. 提供简短提示卡片：“技能来自官方精选与自定义来源，可在来源管理中添加更多”。
4. 允许用户**直接搜索、查看详情、安装**技能。

**当前问题**：
- 现有入口并列导致用户不知道仓库与市场关系；需要通过引导文案与默认路径统一心智。 【F:rebuild-task.md†L200-L243】

---

### 2.2 市场浏览与安装（核心高频场景）

**推荐流程**：
1. **市场列表**显示“主来源（优先级最高）技能”而非重复项。 【F:rebuild-task.md†L355-L404】
2. 允许筛选来源：全部/官方精选/用户来源。 【F:rebuild-task.md†L796-L826】
3. Skill 卡片展示来源徽章（官方/用户）。 【F:rebuild-task.md†L785-L805】
4. 点击 Skill → 查看详情 → 安装（仍保留安全扫描与质量评分系统）。

**当前问题**：
- 来源筛选与徽章显示尚未完成，导致来源感知不足。 【F:rebuild-task.md†L112-L125】

---

### 2.3 添加自定义来源（中频场景）

**推荐流程**：
1. 用户在市场点击“添加自定义来源”。【F:rebuild-task.md†L835-L869】
2. 输入 GitHub URL → 系统扫描（显示进度）。
3. 扫描完成后 Toast 提示：“发现 N 个技能，已同步到市场”，提供“立即查看/稍后再看”。【F:rebuild-task.md†L806-L832】
4. 市场自动出现该来源技能（按主来源规则去重）。

**当前问题**：
- “扫描完成后技能去向不明”的问题尚未完全解决，需要新市场数据流落地。 【F:rebuild-task.md†L251-L276】

---

### 2.4 来源管理（原仓库管理 / 低频配置）

**推荐流程**：
1. **来源列表**展示官方精选 + 用户来源，并标记只读/可编辑。 【F:rebuild-task.md†L877-L909】
2. 支持：启用/禁用、重扫、删除来源。
3. 删除来源前提示影响：若已安装技能，将保留快照；未安装技能将被移除。 【F:rebuild-task.md†L1012-L1035】

**当前问题**：
- CASCADE 删除与已安装技能关联存在矛盾，需明确删除保护或软删除策略。 【F:docs/rebuild-task-review.md†L108-L170】

---

### 2.5 技能去重与主来源显示（复杂但必要场景）

**推荐流程**：
1. 当多个来源含同名技能，市场只显示优先级最高版本；
2. 允许用户通过“只显示自定义来源”查看非精选版本。 【F:rebuild-task.md†L355-L404】

**当前问题**：
- 文档中的主来源示例与代码存在一致性风险，需要统一文档示例。 【F:docs/rebuild-task-review.md†L248-L270】

---

### 2.6 管理与维护场景（高级用户/运营）

**推荐流程**：
1. 批量维护精选仓库列表（新增、替换、禁用）。
2. 通过定期同步或手动触发，保持市场最新内容。

**当前问题**：
- 精选仓库 URL 需保证有效性，避免首次启动失败。 【F:docs/rebuild-task-review.md†L62-L105】

## 4. 建议与行动项

### 4.1 产品与体验建议

- **统一心智**：市场页面默认入口，来源管理降级为低频配置入口；引导文案强调“来源=数据源”。 【F:rebuild-task.md†L200-L243】
- **来源标识统一**：技能卡片必须显示来源徽章 + 来源名称，避免“来源不可见”。 【F:rebuild-task.md†L785-L805】
- **筛选优先级**：来源筛选应放在市场顶部筛选区，与搜索/标签并列。 【F:rebuild-task.md†L796-L826】

### 4.2 研发与数据建议

- **严格数据一致性策略**：统一时间戳、精选仓库 URL 校验、删除保护/软删除策略。 【F:docs/rebuild-task-review.md†L14-L170】
- **性能保障**：避免大体量 JSON 直读，逐步迁移到数据库分页与缓存策略。 【F:docs/TOP-10-PRIORITIES.md†L242-L276】

### 4.3 验收建议（面向 QA）

- **场景覆盖测试**：
  - 新用户进入市场 → 看到精选技能 → 成功安装。 【F:rebuild-task.md†L1040-L1068】
  - 添加来源 → 扫描 → 市场同步可见 → 来源筛选有效。 【F:rebuild-task.md†L1070-L1110】
  - 删除来源 → 未安装技能移除、已安装技能保留快照。 【F:rebuild-task.md†L1112-L1147】

---

## 5. 结论

- 当前最大问题是**市场与来源的割裂**导致用户价值链断裂；同时存在**数据一致性与删除策略**的技术风险。 【F:rebuild-task.md†L251-L295】【F:docs/rebuild-task-review.md†L108-L170】
- 通过“市场统一入口 + 来源为数据源”重新梳理用户流程，可把**扫描、同步、安装、管理**串成完整闭环。 【F:rebuild-task.md†L331-L351】
- 建议将本文件作为重构“场景流程”独立文档，后续与 QA 验收标准绑定，避免设计与实现脱节。
